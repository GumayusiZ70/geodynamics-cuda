# 文档说明

`docs/` 不参与编译，它保存的是“代码为什么这样写、如何证明它是正确的、下一步如何修改”的长期知识。对两人协作的数值模拟项目而言，文档和源代码同样需要进入 Git 版本管理。

## 当前文档

| 文件 | 内容 | 何时更新 |
|---|---|---|
| `roadmap.md` | 项目阶段、开发顺序和每阶段的验证目标。 | 任务范围或实现顺序调整时。 |
| `文档说明.md` | 文档分类与维护规则。 | 新增文档类别时。 |

## 后续建议增加的文档

| 建议文件 | 应写内容 |
|---|---|
| `docs/网格与变量布局.md` | `T/p/eta/u/v` 的物理位置、数组尺寸、行优先索引和 halo 约定。 |
| `docs/边界条件.md` | 温度、速度和压力的每种边界条件及其离散式。 |
| `docs/数值离散.md` | 温度方程、Stokes 方程、差分格式、时间步稳定条件和符号定义。 |
| `docs/验证算例.md` | 解析解、制造解、Rayleigh-Benard 等基准的参数、预期量和通过标准。 |
| `docs/实验记录/` | 每次正式实验的参数、Git commit ID、硬件、运行命令和结果摘要。 |

## 编写原则

1. 参数或公式一旦影响结果，就不能只写在聊天记录里，应写入版本控制。
2. 文档描述的变量名、数组尺寸和边界方向必须与代码一致。
3. 修改数值格式时，同时更新相关文档和测试，避免文档过期。
4. 大型二进制输出不提交 Git；提交参数文件、脚本、关键小图和结果说明即可。
